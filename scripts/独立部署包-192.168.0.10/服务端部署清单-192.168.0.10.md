# 服务端部署清单（192.168.0.10，从零开始）

> 目标：让这台空服务器能接收客户端上传，并把数据落进数据库。
> 部署的其实就是本工程（pi-agent-insight）本身——它既是数据接收端，也是看板。
> 部署完成后，独立部署包里的客户端脚本**不需要任何改动**（地址已写死 192.168.0.10:3002）。

---

## 一、需要放置在服务器上的东西（总览）

| # | 东西 | 说明 | 是否开源 |
| --- | --- | --- | --- |
| 1 | Node.js ≥ 20.9（建议 22 LTS） | 运行时，Next.js 16.2.10 / Prisma 5.22 的要求 | ✅ |
| 2 | 本工程源码 | 从 Git 仓库拉取或直接拷贝 `SourceCode` 目录 | ✅（自有代码） |
| 3 | npm 依赖包 | `npm install` 自动下载，无需手工寻找 | ✅ |
| 4 | `.env` 文件 | 一行：`DATABASE_URL="file:../prisma/dev.db"` | 自写 |
| 5 | SQLite 数据库文件 | `prisma db push` 自动生成，**无需安装数据库软件** | ✅（内嵌于 Prisma） |
| 6 | pm2（推荐） | 进程常驻 + 开机自启 | ✅ |

**不需要装的**：MySQL/PostgreSQL 等数据库服务（SQLite 是单文件内嵌）、Nginx（内网直连即可）、Docker（可选而非必须）。

**注意**：`scripts/独立部署包-192.168.0.10/` 里的采集/上传脚本是**客户端**用的，服务器上不需要放。

---

## 二、Linux 服务器步骤（推荐）

```bash
# 1. 安装 Node.js 22 LTS（任选其一）
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash - && sudo apt install -y nodejs
# 或使用 nvm：curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash && nvm install 22

# 2. 获取源码（二选一）
git clone git@github.com:JeremiahLi/LinkAI_Insight_wb.git pi-insight   # 需配好 SSH key
# 或在本地打包拷贝（不要带 node_modules / .next / tsconfig.tsbuildinfo）：
#   tar --exclude=node_modules --exclude=.next -czf source.tgz SourceCode/

# 3. 安装依赖
cd pi-insight && npm install

# 4. 配置数据库连接（SQLite 单文件，落在 prisma/ 下）
echo 'DATABASE_URL="file:../prisma/dev.db"' > .env

# 5. 初始化数据库（建表，生成空的 dev.db）
npx prisma generate
npx prisma db push

# 6. 构建并启动（端口 3002 已写在 package.json 里）
npm run build
npm run start        # 前台验证；确认能起来后改用 pm2 常驻

# 7. pm2 常驻 + 开机自启
sudo npm i -g pm2
pm2 start npm --name pi-insight -- run start
pm2 save && pm2 startup    # 按输出提示执行一条 sudo 命令

# 8. 开放防火墙端口
sudo ufw allow 3002/tcp   # 或云服务器在安全组里放行 3002
```

## 三、Windows 服务器差异

- Node.js 直接下 msi 安装包（https://nodejs.org 装 22 LTS）。
- 其余步骤 2–6 相同（在 PowerShell 里执行）。
- 常驻运行：`npm i -g pm2` 后同样用 pm2；或更省事——用「任务计划程序」开机运行 `npm run start`。
- 防火墙：Windows Defender 防火墙 → 入站规则 → 新建放行 TCP 3002。

## 四、部署完成后验证

1. 服务器本机：`curl http://localhost:3002` 返回页面 HTML。
2. 局域网任一台电脑：浏览器打开 `http://192.168.0.10:3002` 能看到仪表盘。
3. 在某台客户端跑一次 pi，然后看服务器日志：
   ```bash
   pm2 logs pi-insight --lines 20    # 出现 [upload] 相关即收到请求
   ```
4. 数据落库确认：`prisma/dev.db` 文件在增长；网页端 Session 列表出现新会话。

## 五、数据落在哪里 & 如何备份

- **数据库就是这一个文件**：`<项目目录>/prisma/dev.db`（SQLite）。备份 = 直接拷走这个文件（建议服务停止或低峰时拷，或用 `sqlite3 .backup`）。
- 原始记录存在 `Session.rawData` 字段，解析后的 Span 在 `Span` 表，随时可导出二次使用。
- 想把本地已有的 dev.db 带上服务器：第 4 步跳过 `db push`，直接把本地 `prisma/dev.db` 拷到服务器同位置即可。
- 数据量大了想换库：改 `prisma/schema.prisma` 的 `provider`（如 `postgresql`）+ `.env` 连接串，再 `db push`，其余代码不用动。

## 六、常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 客户端始终没有数据上来 | 服务器 3002 没通：检查服务是否启动、防火墙/安全组、`curl http://192.168.0.10:3002` |
| 上传返回 500 | 看 `pm2 logs`，多数是 dev.db 路径/权限问题（确认 `.env` 与 prisma 目录位置一致） |
| `npm run build` 失败 | 检查 Node 版本 ≥ 20.9；删掉 `.next` 重试 |
| 之前积压的数据 | 不用管——客户端每 30 秒自动补传，服务一上线就会灌进来 |
